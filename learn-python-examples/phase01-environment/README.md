## 1. 阶段定位与当前状态

本阶段解决第一个实际问题：如何把自己写的一段 Python 文本，变成可以独立运行、修改并排查错误的程序。

**第一阶段 01-001～01-008 的正文、分步源码或交互命令、排错材料、练习与答案已齐全。** 核心 Linux 实验已验证，具体范围见 [阶段验证汇总](VERIFICATION.md)。各课运行验证不表示读者已经学完；请在 008 的 [阶段验收清单](008-information-card/ASSESSMENT.md) 自行检查。

编写顺序统一为：总路线 → 阶段详细大纲 → 每课讲解与示例源码 → 阶段综合验收。课程必须遵守 [示例编写规范](../AGENTS.md)，不写入个人身份信息。

## 2. 学完应具备的能力

1. 区分编辑器、终端、shell 和 Python 解释器，说明各自做什么。
2. 从空目录创建、保存、运行 `.py` 文件，并能解释执行命令的组成。
3. 用带中文注释的简单程序输出信息，修改后保存并重新运行。
4. 从文件路径、行号和错误类型入手，定位常见的运行失败。
5. 判断终端与编辑器实际使用哪个解释器，创建并使用一个虚拟环境。
6. 在另一位置重新建立练习目录，按照自己的说明复现运行过程。

本阶段不追求复杂业务。信息内容全部使用虚构数据；信息卡里的数字先作为固定文本输出，不提前要求掌握变量、计算、输入、条件、循环或函数定义。

## 5. 每课详细大纲

### 01-001：认识解释器、终端与第一个程序

**前置与问题：** 无。为什么在编辑器里输入文字后，电脑不会自动执行它？

**理论范围：** Python 语言与解释器的区别；终端承载命令交互、shell 处理命令、编辑器修改文件；文件名与扩展名；保存到磁盘后由解释器读取。用“源文件 → 启动解释器 → 执行语句 → 显示结果”说明过程，暂不讲字节码、虚拟机与编译缓存。`print` 先解释为输出工具，逐一说明括号和成对引号的用途。

**理论小结：** 写代码、保存文件和执行文件是三个动作；运行时要明确哪个解释器读取哪个文件。

| 步骤 | 要抄或操作什么 | 观察结果与解释 |
| --- | --- | --- |
| 准备 | 安装或确认 Python 3；选择一个编辑器；检查版本 | 区分命令成功、命令不存在与进入交互模式，不只展示安装截图 |
| step01-hello | 从空目录创建 `main.py`，抄一条带中文注释的输出语句并运行 | 看到一行固定文本，指出代码、命令和输出各在哪里 |
| step02-change-output | 在独立步骤目录保存完整改版，修改问候内容并重新运行 | 观察输出变化；复述保存与再次执行为何必要 |

**错误与练习：** 检查未保存、运行了旧文件、误存成 `.py.txt`。独立将问候语改为另一句固定文本，说明使用的运行命令与所在目录。

**验收与边界：** 能从空目录复现两步并解释流程。001 只覆盖单行固定输出；多行模拟订单信息放到 002，不提前使用变量、f-string、类或导入语句。

### 01-002：打印多行模拟信息

**前置与问题：** 已完成 001。如何把一句输出扩展成结构清晰的信息卡？

**理论范围：** 字符串字面量、成对的英文引号、`print(...)` 的基本调用形态、默认换行、连续语句的执行顺序；`#` 注释与字符串中 `#` 字符的区别。解释空字符串的输出与空白代码行的区别。初学阶段一条输出语句写一行；转义、多参数 `sep/end` 与格式化留到相关后续课。

**理论小结：** 引号包围的是文本，注释用于解释源码，输出顺序来自语句的执行顺序。

| 步骤 | 要抄或操作什么 | 观察结果与解释 |
| --- | --- | --- |
| step01-multiple-lines | 分别输出标题、模拟订单编号与城市 | 一条语句对应一次输出，调整语句顺序后对照行序 |
| step02-commented-card | 保留完整源码，为关键语句加原因注释并添加一个空输出行 | 注释不作为输出文本出现；空输出行与代码空行行为不同 |

**错误与练习：** 复现中文弯引号、漏引号与把注释内容当输出。增加一行固定“状态”文本，调整行序并预测结果后再运行。

**验收与边界：** 能解释每一行输出来源，所有业务数字仍是字符串中的固定文字。字符串方法和复杂转义留到阶段 03；只使用虚构订单数据。

### 01-003：从不同目录运行同一个文件

**前置与问题：** 已完成 002。文件明明存在，为什么换一个终端目录却提示找不到？

**理论范围：** 当前工作目录、文件所在目录、相对路径与绝对路径、路径中空格的引用。解释 shell 拆分命令参数和相对路径解析的起点。区别“解释器命令没找到”和“解释器启动后找不到脚本”。

**理论小结：** 运行命令里的脚本路径必须从当前工作目录解释；源码内容不变，路径写法仍可能需要改变。

| 步骤 | 要抄或操作什么 | 观察结果与解释 |
| --- | --- | --- |
| step01-same-directory | 确认位置、查看文件、在脚本目录运行完整信息卡 | 对齐命令中的文件名和目录中的真实文件名 |
| step02-parent-directory | 使用该步骤完整副本，从父目录通过相对路径运行，再用绝对路径运行 | 两种路径指向同一副本，输出一致 |
| step03-space-in-path | 把完整副本放入带空格的演示目录，比较错误与正确的路径引用 | 解释为什么未正确引用时参数可能被拆开 |

**错误与练习：** 复现路径少一层、大小写不匹配及错误工作目录。移动自己的练习副本，重写命令并运行，不修改源码。

**验收与边界：** 能从两个工作目录运行指定副本。`pathlib`、`__file__`、文件读取及包导入留到阶段 06。

### 01-004：交互模式与脚本模式

**前置与问题：** 已完成 003。为什么相同的文本表达式在交互窗口里显示结果，放进文件却没有输出？

**理论范围：** REPL 的输入、求值和回显；shell 提示符与 Python 提示符；裸字符串表达式的表示与 `print` 输出的区别；会话与脚本的执行方式。只用已认识的字符串，不借此提前讲完整表达式体系。

**理论小结：** 交互环境可以显示表达式结果，脚本需要显式输出；提示符不是要抄进源码的内容。

| 步骤 | 要抄或操作什么 | 观察结果与解释 |
| --- | --- | --- |
| step01-interactive | 进入交互模式，分别输入字符串表达式和输出语句，退出回到 shell | 对比回显形式与文本输出，明确每条输入交给谁处理 |
| step02-script | 在完整脚本中先放裸字符串表达式，再放输出语句 | 只有显式输出产生相应终端文本 |

交互步骤提供独立输入块与会话输出记录；只需要交互操作时不强行创建无意义的 Python 文件。

**错误与练习：** 在交互窗口误输入 shell 命令，或把 `>>>` 抄入脚本。先判断当前环境再修正，解释为何不该复制提示符。

**验收与边界：** 能进入、识别、退出两种环境，并预测固定文本在两种模式下的表现。不讲会话变量、调试器与 Notebook 状态。

### 01-005：认识语法错误与异常回溯

**前置与问题：** 已完成 004。报错时应该先看哪里，为什么有时前面的输出也没有出现？

**理论范围：** 普通脚本执行前的语法检查与运行期异常；文件路径、行号、源码片段、错误类型与原因文本。用语法错误和拼错 `print` 的运行期错误对照，观察前后输出。说明不同 Python 版本的提示细节可能不同，不要求逐字一致。

**理论小结：** 先判断失败发生在哪个环节，再根据证据定位；不靠随意重装解释器处理源码错误。

| 步骤 | 要抄或操作什么 | 观察结果与解释 |
| --- | --- | --- |
| step01-syntax-error | 故意漏掉引号或括号，再保存完整修复版 | 语法检查失败，正常执行尚未开始 |
| step02-runtime-error | 在两条正常输出之间拼错输出函数名，再保存修复版 | 前一条已执行，失败处中断，后一条未执行 |
| step03-unexpected-indent | 给顶层语句加入多余缩进，再保存修复版 | 解释该位置为什么不应缩进，不展开控制流代码块 |

故意失败文件独立标识；说明预期错误及非零退出，不把它们纳入“所有文件都应成功运行”的检查。

**错误与练习：** 给出三个有单一错误的小脚本，要求记录错误类型、位置、原因与修复结果。

**验收与边界：** 能解释语法期失败与运行期失败的差别。`try/except`、异常链与自定义异常留到阶段 06；此处不吞掉异常。

### 01-006：检查并选择项目解释器

**前置与问题：** 已完成 005。终端和编辑器都能运行 Python，怎样确认它们用的是同一个环境？

**理论范围：** 可执行文件路径、版本与命令查找的基本关系；编辑器运行配置与终端命令是分别选择解释器的入口。版本号相同并不证明路径相同。路径不存在、选择错误与源码错误需要分开判断。

**理论小结：** 环境诊断需要查看实际执行路径，不能只根据编辑器界面上的名称猜测。

| 步骤 | 要抄或操作什么 | 观察结果与解释 |
| --- | --- | --- |
| step01-terminal-check | 运行带逐行注释的 `sys` 诊断脚本，观察解释器路径与版本 | 将输出当作本机证据，预期结果使用字段说明而非固定个人路径 |
| step02-editor-check | 使用完整副本，在编辑器选择解释器并运行，再与终端比较 | 路径一致则完成；不一致则调整选择并重新检查 |

`import sys`、属性访问属于本课明确标记的最小工具知识：解释“导入标准库模块以读取解释器信息”，但不展开模块搜索与包设计；不默默塞入未解释代码。完整模块机制留到阶段 06。

**错误与练习：** 提供通用的路径不一致案例；本机只有一个解释器时不要求额外安装第二个，仅完成实测对照和案例判断。不得删除系统解释器来制造或修复问题。

**验收与边界：** 能提供两种入口的诊断结果并判断是否一致。记录不包含真实用户名、凭据或个人目录；公开文档使用虚构路径并注明为示意。

### 01-007：创建并使用隔离环境

**前置与问题：** 已完成 006。多个项目为什么需要各自的依赖环境，激活环境到底改变了什么？

**理论范围：** 项目目录与虚拟环境目录的区别；venv 提供项目使用的解释器入口和独立包安装位置；激活对当前 shell 命令查找的影响；直接指定环境解释器也能运行。说明它不是容器或安全沙箱，环境可重新创建，不应把业务源码放进去。

**理论小结：** 环境解决依赖归属；激活是调用便利方式，真正执行的仍是某个明确路径的解释器。

| 步骤 | 要抄或操作什么 | 观察结果与解释 |
| --- | --- | --- |
| step01-create-environment | 用选定解释器创建 `.venv`，不激活直接调用其解释器运行完整诊断脚本 | 路径转向练习环境，解释 `-m venv` 的作用 |
| step02-activate-and-check | 激活后运行完整副本，再用该解释器的 `-m pip --version` 检查包工具位置 | 观察命令解析与 pip 归属，不安装第三方依赖 |
| step03-without-activation | 新开终端，以环境解释器的明确路径运行，再退出已激活的 shell 环境 | 区分当前 shell 状态与磁盘中的环境目录 |

激活被系统策略阻止时提供直接调用环境解释器的等效路径；缺少 venv 或 pip 时说明平台差异与官方修复入口，不能把其中一项缺失一概判断为代码错误。各步提供完整业务/诊断源码；环境可以共用，但要写明独立重建命令。

**错误与练习：** 识别在错误目录创建环境、编辑器仍指向其他解释器、误把退出激活当成删除环境。重新创建一个练习环境后运行同一信息卡。

**验收与边界：** 能用激活和直接调用两种方式运行，解释 pip 应归属于哪个解释器。依赖冲突的复杂实验、第三方安装与锁文件留到阶段 10。

| --- | --- | --- |

| step02-revised-card | 保留第一版，完成新增固定字段和调整顺序的完整第二版 | 对照需求确认变化，原版仍能独立运行 |

**故障要求：** 复现一次错误脚本路径和一次源码语法错误，记录原因与修复。用虚拟环境运行正确版本，并能够从不同工作目录启动。

**验收与边界：** 按下面的阶段验收表完成。验收源码不使用变量、条件、循环、函数定义或类；解释器诊断使用 006 已讲过的独立脚本，不与信息卡业务混写。

## 6. 每课如何展开讲解

每课按以下顺序成文，不能只有步骤标题或源码堆叠：

1. 说明本课问题、目标、前置知识和最终看到的效果。
2. 讲透本课核心理论，解释术语、执行过程和易混淆概念，然后做理论总结。
3. 实操每一步说明目标、工作目录、新建文件、完整代码/命令、预期结果与原理，再做小总结。
4. 将故意失败案例与正确代码分开，给出观察证据、修复过程和修复原因。
5. 提供可独立完成的小练习及单独参考答案。
6. 用本课总结回顾能力、边界和自测问题，说明下一课为何需要继续学习。

代码首次出现的组成部分需要详细中文注释；已讲过的语法简要复述即可。命令逐条解释作用和参数，输出单独展示；不能让读者从一大段最终源码中自己猜抄写顺序。

## 8. 阶段综合验收

| 能力 | 验收动作 | 通过标准 |
| --- | --- | --- |
| 创建与运行 | 从新的练习目录创建信息卡文件 | 保存后运行，输出与文字需求一致 |
| 理解输出 | 预测更改语句顺序和添加空输出行的结果 | 预测与实际一致，能解释注释不参与输出 |
| 路径理解 | 从脚本目录和父目录分别运行指定文件 | 两次指向同一版本，能指出相对路径起点 |
| 错误定位 | 修复路径错误和语法错误 | 能区分错误环节，记录原因及修复证据 |
| 解释器诊断 | 对比终端与编辑器结果 | 能说明实际解释器位置；公开说明不包含个人路径 |
| 环境隔离 | 在练习虚拟环境中运行 | 能解释激活与直接调用的关系，不依赖第三方库 |
| 需求变更 | 新增一个固定字段并保留旧版 | 两版独立运行，代码注释和运行说明同步更新 |
| 独立复现 | 按自己写的 README 重建练习 | 步骤没有遗漏，能解释命令与每条输出语句 |

任一项未通过时回到对应课修正，不按“已经抄完”标记掌握。此阶段不安排用户输入的空值、业务数值边界测试；固定输出可检查空行、中文、行序和不同运行目录，避免验收偷偷引入后续知识。
