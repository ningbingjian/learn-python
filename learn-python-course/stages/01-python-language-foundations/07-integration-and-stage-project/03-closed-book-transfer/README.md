# Unit 03 — 能否闭卷完成一个未在正文出现的变化？

## 新需求必须真的没有做过

priority 从 Module 01 就已存在；按状态筛选也已在上一章完成。因此不能再把“新增 priority 与 list --pending”当成闭卷新需求。本题改为新增截止天数字段、按既有优先级排序、筛选到期未完成任务。

请先复制最终源码到自己的练习目录，关闭参考解，只依据以下契约工作。可以查 Python 语法文档，不得照抄参考实现。学习验证关注你如何发现变化边界，不以键入速度判分。

## 需求契约

新增 `due_in_days`，类型为非负整数或 None。它是本次会话的相对天数标签，不读取系统日期、不随时间倒计时；0 表示今天到期，None 表示没有截止信息。负数、布尔值、浮点值或非整数字符串均不合法。

add 与 edit 在备注后多问一次 `Due in days (blank for none): `。空白归一化为 None，编辑时表示清除截止信息；标题、优先级、备注和截止信息必须一起验证、一起提交。已有调用者省略此参数时仍能工作，默认无截止信息。

显示行在既有内容后增加 ` | due=none` 或 ` | due=0` 等文本。

新增两条命令：

| 命令 | 结果 |
|---|---|
| list --priority | 所有任务按 priority 升序，1 最高；相同优先级保持原新增顺序 |
| list --due | 只显示未完成且 due_in_days == 0 的任务，保持原新增顺序 |

两者不改变正式集合顺序；已有 list、list --pending、list --done 继续工作，不支持多个筛选参数组合。这里不引入日期库、持久化、继承或第三方 CLI 框架。

## 提交前必须给出的证据

先写行为测试，再实现也可以；无论顺序如何，最终提交必须包含：

1. 字段解析：空白→None、0→0、2→2，拒绝 -1、2.5、abc。
2. 模型：显式 False/True 不是合法天数；编辑非法截止值时所有旧字段保持不变。
3. 排序：新增优先级 2、1、1 的任务，结果 ID 为 2、3、1；原 list 仍为 1、2、3。
4. 到期：今天未完成的显示；今天已完成、未来到期、无截止的都不显示。
5. 连续会话：add → 两种新 list → edit → complete → list --due → quit。
6. 输入结束：新提示处 EOF 不消耗 ID、不留下半次编辑。
7. 回归：既有领域与导入测试通过；旧会话录入需补新的截止输入，旧展示断言需反映新字段，而不是删掉旧命令覆盖。

不要用 `if task.due_in_days` 判断是否到期，合法 0 为假值。不要直接对内部列表调用 sort 后返回，否则普通 list 的顺序也被改了。以上是契约提醒，不提供逐行实现。
