# Python 示例编写规范

本规范适用于本目录及所有子目录，是后续生成课程、源码、命令和练习的约束。用户当前明确要求优先。

## 隐私约束

- 未经用户明确要求，不得在公开文档、示例、注释或提交说明中写入用户真实姓名、联系方式或其他个人身份信息；统一使用通用称呼或虚构示例数据。

## 1. 读者与教学目标

- 读者是有 Java 经验、正在系统学习 Python 的中文学习者。不能因读者会 Java 而跳过 Python 基础。
- 核心目标是让读者边理解边抄写，最终能独立修改、解释和排错，不以堆积代码或技术名词为目标。
- 首次出现的核心概念必须讲清：是什么、解决什么问题、如何运行、为什么这样写、边界和易错点。
- 已学知识简单复述原理并链接前课；不要重复大段基础，也不能只说“前面讲过”。
- Java 对照用于澄清差异，不得把 Python 机制直接等同于 Java 或 Lombok、Spring 等机制。

## 2. 每课必需结构

1. 本课目标、前置示例编号、待解决的具体问题。
2. 环境信息：实际验证的 Python 与依赖版本、操作系统或 shell、工作目录、已有与待创建文件。
3. 核心理论：具体例子和运行过程；涉及引用、调用、调度时解释状态如何变化。
4. 理论部分总结：归纳概念关系，说明接下来实操验证什么。
5. 逐步实操：每步包含“目标 → 创建或修改文件 → 完整代码或命令 → 运行 → 预期结果 → 原理解释 → 小总结”。
6. 常见错误：给可复现的失败、报错关键部分、定位过程和修复原因。
7. 变式练习：至少一个小需求，明确输入、输出、验收标准；答案单独放置并解释。
8. 本课总结：已解决的问题、核心原理、适用边界、自测问题、下一课承接点。

不要为了套模板把简单课写得冗长；复杂主题应拆成多个小步骤，不能省掉本课核心理论。

## 3. 代码与命令的注释

- 所有示例源码提供详细中文注释：文件用途、输入输出、运行入口；新语法解释每个关键组成部分，业务逻辑解释目的与原因。
- 重点说明参数含义、返回值、数据类型或结构、状态变化、资源释放、异常与边界。注释不能只把代码翻译成汉语。
- 函数和类按复杂度写文档字符串；不用尚未讲解的大量高级语法来节省行数。
- 命令执行前给出明确工作目录。每条命令前写中文注释说明作用；首次出现的参数解释含义。
- macOS/Linux shell 与 Windows PowerShell 的差异分别标明，不能把不同 shell 的语法混在同一代码块。
- 不在复制用的命令中混入 `$`、`>>>` 等提示符；输出放到独立 `text` 代码块。
- 命令中的占位符必须注明替换规则。服务例子优先提供本地模拟或离线模式，不能默认有付费账号。
- 提供完整可运行源码，不用省略号代替关键实现；文档片段必须注明所在文件与上下文，最终提供完整版本。

## 4. 演进与项目组织

- 一次演进解决一个具体问题，先指出前一版的限制，再说明新方案为什么有效。
- `step01-*`、`step02-*` 等目录分别保留每一步完整版本，不能覆盖旧版而只留下最终答案。
- 每步能按文档独立运行；不能暗中从其他步骤导入业务代码，或依赖先运行某一步产生的未说明状态。
- 环境或测试数据可在明确说明后共用，不要求每个小脚本都有一个独立依赖项目。
- 基础期只用标准库；引入第三方包时讲清解释器、虚拟环境、安装位置、版本约束和复现方法。
- 实际需要不同依赖时再隔离环境。不要在整个学习区强制安装所有方向的依赖。
- 本次只规划的示例不得创建假源码、空测试或标为已完成。

## 5. 验证与真实性

- 发布可运行示例前实际执行文档里的主要运行路径，核对结果。记录验证环境与命令，不能编造“已测试”。
- 涉及文件、数据库、网络、并发、时间或随机值时，写明初始状态、初始化、清理、重复运行行为和输出不确定部分。
- 并发示例解释超时、取消、失败、退出与资源释放；网络演示包含本地可控的成功与失败情况。
- 故意失败的教学代码与正常示例分开，注明预期异常和触发原因。
- 入门课不强制引入测试框架；工程化之后对业务边界、错误分支和资源管理使用有意义的测试。
- 遇到环境限制如无数据库、无容器运行时，明确未验证的范围，不声称端到端通过。
- 源码分析固定 Python/库的版本或提交，给文件路径、入口、调用链和复现实验。区分语言规范、CPython 实现和版本特性。

## 6. 完成与维护

- 新增课程后更新学习区与阶段导航、状态和前后课链接，编号不要因增补而批量重排。
- 路线新增主题可使用阶段内 `009` 及后续编号；拆课说明与原编号的关系。
- 每阶段综合练习应检验已有知识，不能偷偷引入未讲过的框架或服务。
- 外部技术文档优先官方来源；课程实际生成时核对版本兼容性，不把路线中的技术名当成已验证的依赖组合。
