## 2. 理论：语句、文本和显示布局不是同一件事

### 2.1 字符串字面量是什么

直接写在源码中的固定文本，例如 `"城市：杭州"`，叫字符串字面量。引号划定文本范围，里面的中文、数字、标点是内容。本课 `"订单编号：DEMO-002"` 中的数字只是文本的一部分，不做计算。

单引号和双引号都可以界定普通字符串，但左右要成对。为了便于抄写，本课统一英文双引号；中文弯引号不能代替语法引号。`print` 收到字符串后显示内容，界定字符串的引号本身不显示。

### 2.2 为什么多条 print 会产生多行

在本课没有分支、循环、异常的顺序代码中，语句按书写顺序执行。执行第一条 `print`，输出第一段文本并默认换行，再执行第二条。Python 不会根据“标题”“城市”的中文含义自动调整次序；调整源码顺序才会改变输出顺序。

不要把“源文件一行”直接等同于“输出一行”：注释行不输出，空白代码行也不输出，而一次 `print("")` 即使文本长度为零，仍会执行默认换行。函数默认行为参考 [print 官方说明](https://docs.python.org/3/library/functions.html#print)。

### 2.3 为什么有的 # 会显示，有的不会

`#` 位于字符串外时，可以开始行注释，后面的文字用于解释代码；位于引号包围的字符串内时，它就是文本字符。解释器会先根据语法判断它处在哪个位置，不是见到任意 `#` 都删掉后面内容。

| 源码形式 | 做了什么 | 终端变化 |
| --- | --- | --- |
| `# 标题说明` | 注释 | 无 |
| 一条空白源码行 | 分隔源码，方便阅读 | 无 |
| `print("")` | 输出空字符串，再默认换行 | 产生空输出行 |
| `print("# 模拟信息")` | 输出字符串里的井号和文字 | 显示井号 |

### 理论总结

源码布局帮助人阅读，输出布局来自实际执行的输出调用。接下来先输出三行，再加注释、分隔空行和一个字符串内的井号，对比每个变化的原因。

## 3. 第一步：输出三行模拟信息

在本课目录创建 `step01-multiple-lines/main.py`。先预测行数与顺序，再抄完整代码：

<!-- source: step01-multiple-lines/main.py -->
```python
# 用途：顺序输出三行模拟信息；不读取输入，不修改文件。
# 运行：在本目录执行 python3 main.py；Windows 使用 python main.py。
# 标题先输出，因为这条调用写在其他输出调用之前。
print("模拟订单信息")
# 编号整体是固定文本，DEMO-002 不参与任何数值运算。
print("订单编号：DEMO-002")
# 默认换行使城市出现在下一行，不需要在这里拼接换行符。
print("城市：杭州")
```
**重新从本课目录开始**，选自己系统的一组命令执行：

```bash
# 进入本步目录；cd 改变当前 shell 的工作目录。
cd step01-multiple-lines
# 执行本目录的 main.py，文件必须先保存。
python3 main.py
```

```powershell
# 进入本步目录；这里使用 PowerShell 的 Set-Location。
Set-Location step01-multiple-lines
# 执行已经保存的 main.py。
python main.py
```

预期输出：

```text
模拟订单信息
订单编号：DEMO-002
城市：杭州
```
**观察与原理：** 三条调用产生三行。临时交换编号和城市两条语句，保存后运行，行序也会交换；再恢复原版。注释不是输出标签，只有引号中的内容被显示。

**小总结：** 行序由代码执行顺序决定。第一版很紧凑，下一步让输出有分隔，同时增加帮助理解的注释。

## 4. 第二步：加注释与空输出行

创建独立的 `step02-commented-card/main.py`，保留第一版。下面有一条空白源码行和一条空字符串输出，抄完后分别找出它们：

<!-- source: step02-commented-card/main.py -->
```python
# 用途：输出有分隔空行的信息卡，观察注释和字符串内井号的区别。
# 运行：在本目录执行 python3 main.py；Windows 使用 python main.py。
# 井号处于字符串内部，因此它会随标题一起显示。
print("# 模拟订单信息")
# 空字符串没有可见字符，但 print 的默认换行仍会执行。
print("")

# 上面的空白源码行只分隔代码，不会额外增加输出行。
print("订单编号：DEMO-002")
# 城市写在编号后面，实际输出也遵循这个顺序。
print("城市：杭州")
```
**重新从本课目录开始**，选自己系统的一组命令执行：

```bash
# 进入本步目录；cd 改变当前 shell 的工作目录。
cd step02-commented-card
# 执行本目录的 main.py，文件必须先保存。
python3 main.py
```

```powershell
# 进入本步目录；这里使用 PowerShell 的 Set-Location。
Set-Location step02-commented-card
# 执行已经保存的 main.py。
python main.py
```

预期输出（标题后恰好一个空行）：

```text
# 模拟订单信息

订单编号：DEMO-002
城市：杭州
```
**观察与原理：** 输出中的 `#` 来自标题字符串，不是代码注释。删除空白源码行再运行，输出不变；把 `print("")` 临时改为注释后运行，空输出行消失。完成后恢复完整代码。

**小总结：** 你现在能独立控制文字、顺序和分隔。代码注释应说明“为什么这样写”，不能只给每行贴一个“打印”标签。

## 5. 排错实验：引号错误和误把注释当输出

新建 `errors/broken.py`，这是故意失败文件，只用于单独观察。正确文件也单独保留：

<!-- source: errors/broken.py -->
```python
# 故意失败：这里使用中文弯引号，不能界定 Python 字符串。
# 在 errors 目录运行 python3 broken.py；Windows 使用 python broken.py。
# 预期 SyntaxError，没有正常输出；不要用它代替正确步骤文件。
print(“模拟订单信息”)
```
<!-- source: errors/fixed.py -->
```python
# 修复方式：只把界定文本的引号换成成对的英文双引号。
# 在 errors 目录运行 python3 fixed.py；Windows 使用 python fixed.py。
# 中文文字可以保留，因为它位于合法字符串内部。
print("模拟订单信息")
```
**重新从本课目录开始**，选自己系统的一组命令执行：

```bash
# 进入本步目录；cd 改变当前 shell 的工作目录。
cd errors
# 执行本目录的 broken.py，文件必须先保存。
python3 broken.py
```

```powershell
# 进入本步目录；这里使用 PowerShell 的 Set-Location。
Set-Location errors
# 执行已经保存的 broken.py。
python broken.py
```
预期非零退出，错误末尾包含 `SyntaxError`（本环境包含 `invalid character`）。解释器无法把弯引号识别为字符串边界，这不表示中文内容不能使用。**留在 errors 目录**执行修复版：

```bash
# 运行已经修正引号的独立文件，应显示“模拟订单信息”。
python3 fixed.py
```

```powershell
# 运行修复版，应显示“模拟订单信息”。
python fixed.py
```

漏掉结尾引号也会破坏字符串边界，通常报 `unterminated string literal`；先从成对引号检查，完整错误分类放到 005。

另一个常见误会是只写 `# 状态：待投放` 却期望屏幕出现状态。它是注释，需调用 `print` 并把状态放进引号中。本课正常程序重复运行结果不变，不产生文件；故障文件的失败是预期行为。
