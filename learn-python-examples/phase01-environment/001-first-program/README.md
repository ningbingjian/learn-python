## 1. 本课要解决什么问题

在编辑器里写下代码之后，怎样让电脑执行它？为什么修改了文字，运行结果有时却没有变？

本课从空目录开始，只输出一行固定文本。先完成第一版，再保留第一版、创建修改后的第二版。学完后，你应能独立完成“创建 → 抄写并理解 → 保存 → 运行 → 修改 → 再运行”，而不只是点一次运行按钮。

第一步预期看到：

```text
你好，Python！
```

第二步预期看到：

```text
我已经运行了第一个 Python 程序。
```

没有 Python 前置知识要求，也不需要先学 Git。本课不安装第三方库；暂不讲变量、循环、函数定义、类或虚拟环境。你现在只需要一个 Python 3 解释器、一个编辑器和终端。

## 2. 核心理论：代码怎样变成运行结果

### 2.1 Python 语言与 Python 解释器

**Python 语言是一套写程序的规则；Python 解释器是运行这种程序的软件。** 就像 SQL 是表达查询的语言，而数据库软件负责处理查询，两者不能混为一件事。

例如下面是一条 Python 语句，它本身只是文本：

```python
# 调用内置输出函数，把引号里的固定文本显示出来。
print("你好，Python！")
```

把这段文本存入文件不会立即输出问候语。需要启动解释器，让它读取文件并执行其中的语句。解释器会检查代码是否符合语法；遇到不能处理的内容，会给出错误信息。

这里先理解“解释器读取并执行程序”。它内部如何处理字节码属于后面的内容；不要把这段入门说明理解为 Python 永远逐行读一行文本就直接执行一行。

### 2.2 四个工具各自做什么

| 名称 | 本课中的职责 | 你会做的操作 |
| --- | --- | --- |
| 编辑器 | 编辑并保存源码文件 | 在 VS Code 中写 `main.py` |
| 终端 | 提供输入命令、显示输出的界面 | 打开终端窗口或 VS Code 的终端面板 |
| shell | 处理你输入的命令，寻找并启动相应程序 | bash/zsh 或 PowerShell 处理运行命令 |
| Python 解释器 | 读取并执行 Python 代码 | 执行 `main.py` 中的输出语句 |

终端与 shell 常一起出现，所以口语中会混称。但终端是交互界面，shell 是在里面接收和处理命令的软件。运行 Python 时，结果也会显示在这个终端里。

**编辑器不是解释器。** 编辑器能让代码显示不同颜色、提供提示，但真正运行 Python 仍需要解释器。本课先在终端明确输入命令，方便看到“谁运行了哪个文件”；编辑器的运行配置会在 01-006 深入讲。

### 2.3 `.py` 文件和保存有什么关系

`main.py` 是一个普通文本文件。`main` 是这次起的文件名，`.py` 是常用的 Python 源文件扩展名。`main` 并不是必须使用的特殊名字，也不需要像 Java 那样先定义类和 `main` 方法。

编辑器里正在修改的内容与磁盘上保存的文件可能不同。你敲下字符后，如果还没有保存，磁盘上可能仍然是旧内容。本课的终端命令读取磁盘文件，因此必须先保存，再运行。

文件需要以纯文本形式保存，编码选择 UTF-8。编码可以先理解为“文本转成文件字节、再还原回来时采用的规则”。本课只确认 UTF-8，不展开编码算法。

### 2.4 一条运行命令发生了什么

在包含 `main.py` 的目录中，macOS/Linux 的示例命令是：

```bash
# 启动已经确认可用的 Python 3，并把当前目录中的 main.py 交给它运行。
python3 main.py
```

| 部分 | 含义 |
| --- | --- |
| `python3` | 要启动的解释器命令，具体名称需在本机确认 |
| 中间的空格 | 将程序命令与后面的文件参数分开 |
| `main.py` | 交给解释器运行的文件名，这里指当前目录中的文件 |

执行时，shell 先寻找 `python3` 对应的程序，再把文件参数交给它。解释器读取源码，执行输出语句，文本出现在终端。程序执行结束后，终端再次等待你输入命令。

这里没有让程序读取键盘输入。如果运行后终端重新出现命令提示位置，是正常完成，不是程序“没保持住”。

### 2.5 理论总结

写代码、保存文件、运行文件分别完成不同工作。编辑器负责写和存，shell 启动解释器，解释器读取文件并执行，终端显示结果。接下来两步实验会验证这个过程，特别是“修改后为什么要保存并重新执行”。

### 3.2 打开终端并检查解释器

**macOS：** 打开 Spotlight，输入“终端”或 “Terminal”，打开系统终端。**Linux：** 从应用菜单打开终端。当前目录任意，执行：

**Windows：** 从开始菜单搜索并打开 PowerShell。当前目录任意，执行：


```powershell

```

如果只有 `py` 成功，后文所有 Windows 命令把开头的 `python` 换为 `py`，其他部分不变。不要检查用一个入口，后面又无意换成另一个入口。

```python
# 退出当前交互会话，回到 shell；这行不需要写进 main.py。
exit()
```

### 3.3 没有可用 Python 3 时怎样安装

已有版本检查成功时跳过本节，只按自己的操作系统选择一条路径。

- **Windows：** 按 [Windows 官方安装说明](https://docs.python.org/3/using/windows.html) 安装 Python Install Manager。完成后重新打开 PowerShell，执行 `python --version`；官方管理器在没有运行时时可能先安装运行时，等待完成再确认版本。旧版安装器和旧 `py` 启动器也可能已经存在：已有 Python 3 可运行时直接使用，不要求为了本课卸载重装。
- **Linux：** 先确认发行版是否已经提供 `python3`；缺少时按发行版文档安装 Python 3 软件包。不同发行版使用不同包管理器，不照抄别的发行版的管理员命令。平台说明见 [Unix 官方说明](https://docs.python.org/3/using/unix.html)。安装后重复本节版本检查。

安装完成的验收是终端实际返回 Python 3 版本，而不只是安装向导显示“完成”。如果仍失败，查看对应官方页面中的排查说明；先记录具体错误，不通过删除系统解释器解决。

## 4. 第一步：从空目录写出并运行问候语

### 4.1 创建自己的抄写位置

目标：自己建立第一版文件，而不是只打开仓库现成答案。

1. 在文件管理器中选一个可写位置，用“新建文件夹”创建 `python-practice`。macOS 使用 Finder，Windows 使用文件资源管理器，Linux 使用桌面文件管理器。已有同名练习时另选新位置，不覆盖已有文件。
2. 在 VS Code 选择“文件 → 打开文件夹”，选中刚建的 `python-practice`。
3. 在左侧资源管理器中使用“新建文件夹”按钮，依次创建 `001-first-program`，再在其下面创建 `step01-hello`。
4. 右键 `step01-hello` 选择“新建文件”，名称输入 `main.py`。
5. 现在编辑器中打开的应是 `python-practice/001-first-program/step01-hello/main.py`。这个是你自己抄写的文件；仓库的对应文件是供核对的答案。

文件夹路径中的 `/` 在这里用来说明层级，不需要把整个路径当作一个文件名输入。

### 4.2 抄写完整源码并理解每个部分

将下面全部内容写入刚创建的 `main.py`。也可以复制后逐行阅读，但要能解释最后一行，再独立做后面的变式练习。

<!-- source: step01-hello/main.py -->
```python
# 文件用途：运行第一个 Python 程序，在终端输出一行固定的问候语。
# 输入：不需要键盘输入，也不读取其他文件。
# 运行：在本文件所在目录执行 python3 main.py（macOS/Linux）；
#       Windows PowerShell 使用已确认可用的 python main.py。
# print 是 Python 内置的输出函数；括号表示调用它，让它执行输出动作。
# 成对的英文双引号把问候语标记为字符串，也就是一段文本。
# 引号用于界定文本的起止，不会作为问候语的一部分输出。
# 默认情况下，print 输出文本后会换行；以 # 开头的这些注释不会输出。
print("你好，Python！")
```

| 写法 | 为什么需要它 |
| --- | --- |
| `print` | Python 已经提供的输出函数名称，不用自己实现；拼写和大小写要正确 |
| `(...)` | 表示调用函数，括号内给出这次要输出的内容；本课先会使用，不学习定义函数 |
| `"你好，Python！"` | 成对英文双引号包围固定文本，Python 将它识别为字符串 |
| `#` 开头的行 | 本例中都是给读者看的注释，不会输出问候语 |

“函数”在这里先理解为可以调用的已有功能；“字符串”先理解为一段文本。文本中的中文逗号、感叹号可以保留，但作为语法的括号和引号应使用英文字符。

### 4.3 保存后，确认终端所在目录

用“文件 → 保存”，或 macOS `Command+S` / Windows、Linux `Ctrl+S` 保存。确认 VS Code 状态栏编码是 UTF-8；如果不是，通过编码菜单选择“以编码保存 → UTF-8”。

在 VS Code 左侧资源管理器中右键 **`step01-hello` 文件夹**，选择“在集成终端中打开”。若已有终端也没关系，但要以刚打开并确认位置的终端为准。

macOS/Linux shell 执行：

```bash
# 显示当前工作目录，应以 001-first-program/step01-hello 结尾。
pwd
# 列出当前目录的文件，应看到 main.py。
ls
```

Windows PowerShell 执行：

```powershell
# 显示当前工作目录，应以 001-first-program\step01-hello 结尾。
Get-Location
# 列出当前目录的文件，应看到完整名称 main.py。
Get-ChildItem
```

这些命令不进入 `main.py`。如果目录不对，重新在目标文件夹打开终端；完整路径原理与切换目录的实验放在 01-003。此处先把运行位置对齐。

### 4.4 运行并对照结果

**当前工作目录：自己的 `001-first-program/step01-hello`。** 先确认已保存文件。

macOS/Linux：

```bash
# 用已确认可用的 Python 3 运行当前目录中的 main.py。
python3 main.py
```

Windows PowerShell：

```powershell
# 使用前面检查成功的入口；若只有 py 可用，把 python 换成 py。
python main.py
```

预期输出只有下面一行；终端自身显示的路径、命令和提示符不属于程序输出：

```text
你好，Python！
```

不要把上面 `text` 框的输出写回源码，源码应保留 `print(...)` 结构。

### 4.5 这一步验证了什么

命令把 `main.py` 交给解释器；解释器识别出字符串，并执行 `print` 调用。引号是界定文本的语法，不包含在输出内容中。注释帮助人读代码，也不会输出。

默认的 `print` 在文本后追加换行，所以光标进入下一行。再次运行会再输出一遍，但文件不会被程序改写；终端保留多次运行的历史，不代表程序内部在累计数据。

**第一步小总结：** 你已经把纯文本源码保存成文件并交给解释器运行。成功的关键证据是指定文件产生了预期的一行输出。

## 5. 第二步：保留原版，修改并重新运行

### 5.1 为什么单独保存第二版

第一步只证明程序能跑起来。第二步验证“改变文件内容，运行结果为什么跟着变”。两步使用独立目录，避免改完后找不到原版对照。

在 VS Code 的 `001-first-program` 文件夹下新建 `step02-change-output`，再在其中创建 `main.py`。第二版不导入第一版，删去或不运行第一版也不会影响第二版。

### 5.2 抄写第二版完整源码

写入自己的 `001-first-program/step02-change-output/main.py`：

<!-- source: step02-change-output/main.py -->
```python
# 文件用途：保留第一版，在独立文件中修改问候语，观察保存并重新运行的效果。
# 输入：不需要键盘输入；本文件可以单独运行，不依赖第一步的文件。
# 运行：在本文件所在目录执行 python3 main.py（macOS/Linux）；
#       Windows PowerShell 使用已确认可用的 python main.py。
# 本次只改双引号里面的文本，print、括号和成对引号的结构保持不变。
# 修改后先保存，再运行：终端运行命令读取的是磁盘上保存的这个文件。
# 每次运行都输出同一行文本，不会修改文件，也不会累计生成其他数据。
print("我已经运行了第一个 Python 程序。")
```

这次不用重新学习 `print`：它仍然负责输出，只是收到的文本变了。修改内容时保留完整的英文括号与双引号，保存文件。

### 5.3 从第二步目录运行

右键 **`step02-change-output` 文件夹**，在集成终端中打开。确认位置与文件后运行。不要沿用还停在第一步目录的终端而不检查。

macOS/Linux shell：

```bash
# 确认当前目录以 001-first-program/step02-change-output 结尾。
pwd
# 确认当前目录中存在这一步的 main.py。
ls
# 运行第二版；同样的文件名会在当前目录中查找。
python3 main.py
```

Windows PowerShell：

```powershell
# 确认当前目录以 001-first-program\step02-change-output 结尾。
Get-Location
# 确认存在这一步的 main.py。
Get-ChildItem
# 运行第二版；只有 py 可用时继续使用 py main.py。
python main.py
```

预期输出：

```text
我已经运行了第一个 Python 程序。
```

再在第一步文件夹打开终端，用前一节命令运行第一版，仍应输出 `你好，Python！`。

### 5.4 原理与小总结

两个文件都叫 `main.py`，但属于不同目录，因此是两个不同的文件。终端中的运行命令相同，实际读取的文件却由运行位置决定。

第二版的新文本来自你保存的新源码，不是解释器记住了刚才在编辑器里打过什么。**第二步小总结：修改正确文件、保存、在正确目录运行，三件事都要对上。**

## 6. 常见问题：观察现象，再定位原因

### 6.1 修改了文字，输出仍然是旧的

先在自己的第二版中把输出文本改成另一句话，然后暂不手动保存，在终端运行。若编辑器开启自动保存，此实验可能直接输出新文字；可以通过“文件 → 自动保存”暂时关闭后重试，最后恢复原设置。

未保存时出现旧输出，是因为磁盘还是旧文件。保存后再运行应该更新。若仍没变，查看终端当前位置，并核对编辑器标签或文件面包屑显示的路径：你可能编辑第二版，却运行了第一版。

修复后恢复第二版的规定文本并保存，方便与仓库答案一致。完整执行记录中的自动实验只验证磁盘文件变化；GUI 自动保存行为未实测。

### 6.2 提示找不到 `main.py`

在步骤目录执行下列故意写错文件名的命令。**这是排错实验，预期失败，不是正常运行命令。**

macOS/Linux：

```bash
# 故意指定不存在的 mian.py，观察文件未找到的错误。
python3 mian.py
```

Windows PowerShell：

```powershell
# 故意把 main 拼错为 mian；预期解释器启动后无法打开这个文件。
python mian.py
```

错误文本通常含 `can't open file` 和 `No such file or directory`，具体路径随电脑不同。此时解释器已经启动，失败的是找文件。重新列出当前目录中的文件，修正为 `main.py`，再运行。

如果实际保存成了 `main.py.txt`，先在编辑器资源管理器中重命名为 `main.py`。不是让程序先读 `.txt` 再自动找 `.py`；文件名必须一致。虽然解释器可以执行具有其他扩展名的纯文本文件，本课统一 `.py`，方便工具识别和减少误操作。

### 6.3 出现 `command not found` 或“无法识别命令”

这与上一种错误不同：shell 没有找到你指定的解释器入口，还没有运行源码。回到版本检查，确认命令与先前成功的一致；安装后新开终端重试。不要通过修改 `print` 解决解释器入口问题。

### 6.4 引号或括号不成对

对照正确源码，检查是否把英文 `"` 改成了中文弯引号，是否漏写了末尾 `")`。这类问题通常会报告 `SyntaxError`。先恢复本课完整正确语句再运行；错误行号与语法期、运行期区别会在 01-005 通过专门实验展开。

**排错小总结：** 先确认解释器是否启动，再确认读的是哪个文件，最后核对文件是否保存及源码是否完整。这样每次检查都有明确目的。
