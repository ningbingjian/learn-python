## 2. 先写出预测

在运行前预测：

```python
0.1 + 0.2 == 0.3
```

数学上的十进制结果显然是 `0.3`，但 Python 的 `float` 通常使用 IEEE 754 二进制浮点表示。很多有限十进制小数在二进制中需要无限展开，只能保存附近的可表示值。

这和十进制中的 `1 / 3` 类似：如果只允许有限位数，就只能保存 `0.333...` 的近似。

## 3. 运行实验

```bash
python float_precision.py
```

预期观察：

```text
total repr: 0.30000000000000004
expected repr: 0.3
exactly equal: False
difference: 5.551115123125783e-17
close enough: True
```

输出中的最后几位和科学计数法来自浮点近似。关键结论不是背下这一串数字，而是：

```text
显示上很接近
≠
二进制浮点对象完全相等
```

## 4. 比较要表达允许误差

源码同时展示：

```python
total == expected
```

和：

```python
math.isclose(total, expected)
```

前者要求精确相等，后者表达“在默认相对与绝对容差规则下足够接近”。具体容差必须由业务语义决定，不能因为 `math.isclose()` 返回 `True` 就认为任何误差都可接受。

## 5. 工程边界

- 计数、索引、离散等级等业务值通常使用 `int`。
- 测量和近似计算可以使用 `float`，比较时要明确误差策略。
- 金额等需要十进制精确规则的领域，不应因为方便就依赖二进制浮点精确相等。
- `Decimal`、舍入规则和金融建模不是当前 Lab 的学习目标，将在真实需求出现时系统处理。
