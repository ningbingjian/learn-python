## 2. 学完应具备的能力

1. 从“名字绑定到对象”的角度解释赋值、再次赋值、类型和别名，不把 Python 名称理解成固定类型的 Java 变量槽。

3. 使用算术、比较和逻辑表达式，说明求值顺序、结果类型和短路行为。

本阶段主要训练语言机制。达到这些目标不代表已经具备生产接口的输入校验、金额处理或异常恢复能力；这些能力会在后续课程结合具体规则补齐。

## 5. 每课详细大纲

### 02-001：保存订单名称与曝光次数

**前置与问题：** 完成阶段 01。订单名称重复写在多处，为什么改了某一处，其他输出没有跟着变？

**核心理论：** 标识符、命名和大小写；赋值左边的名称与右边表达式；先求右边的值再建立绑定；类型属于对象，名称可以再次绑定；print(name) 读取绑定对象，print("name") 输出固定字母。用 type 观察字符串和整数，但不展开 type 的元类用途。讲解整数不可变的最小含义：重新绑定名称不会把旧整数对象就地改成另一个值。

**理论总结：** 名称让数据可复用；赋值是一次绑定动作，不是建立一个会自动持续计算的公式。

| 步骤 | 要抄写的内容 | 要观察与解释的结果 |
| --- | --- | --- |
| step01-literals | 独立保留固定文本信息卡，指出重复数据 | 修改一处固定文本不会修改其他语句 |
| step02-named-values | 给订单名称和曝光次数分别赋值，打印值与 type | 引号内数字与真正整数的类型不同；不在本步转换 |
| step03-rebinding | 建立 original_count 与 copied_count 的绑定，再给 original_count 赋不同整数 | copied_count 仍保留原值；不要讲成赋值做了深拷贝 |

**错误与练习：** 单独复现名称拼错、赋值前读取的 NameError；比较给变量名加引号和读取值的区别。练习修改订单名与曝光次数，预测别名在重新绑定后的值。

**验收与边界：** 能画出或口述名称到对象的关系，区分字符串和整数。暂不教容器、id 数字地址、内存分配器、作用域、类型注解；不把 Java 原始类型赋值规则直接移植过来。

### 02-002：计算总曝光与平均曝光

**前置与问题：** 已学 001。怎样用两个日期的曝光量计算总量和日均，而不是把计算结果写死？

**核心理论：** int 与 float；加减乘除、`//`、`%`、`**`；`/` 的结果与整数相除不一定得到整数类型；优先级与括号；右边表达式按当前绑定求值，结果赋给新名称。用负数最小对照解释 `//` 向下取整，避免误认为总是截断小数部分。

**理论总结：** 表达式产出一个结果对象；先明确数据单位、分母和类型，再选择运算符。

| 步骤 | 要抄写的内容 | 要观察与解释的结果 |
| --- | --- | --- |
| step01-total-and-average | 两日曝光量、天数、总曝光和平均曝光分别命名并计算 | 总量与日均类型可不同；更改输入后需要重新执行计算语句 |
| step02-operators | 单独比较普通除法、整除、余数与幂，加入括号对照 | 日均不应因误用整除而丢失小数；负整除与截断不同 |
| step03-input-change | 保留旧版，在独立版本修改输入、重新计算并对照 | 修改名称绑定不会追溯更新已经求值的旧结果 |

**错误与练习：** 将分母设为零放入 errors 的独立失败文件，观察 ZeroDivisionError 及之前输出；正确示例分母为正。练习给出新两日数据，先手算再运行，并解释每个值的单位。

**验收与边界：** 能解释结果和结果类型，知道零除为何失败。此课不引入 if、异常捕获和自动兜底；二进制浮点误差留到 007，不承诺所有小数运算精确。

### 02-003：判断订单是否启用

**前置与问题：** 已学 002。怎样把“已启用并且有剩余额度”表示为一个可观察的结果？

**核心理论：** True/False 的大小写；比较符号与 `=` 赋值的区别；`and`、`or`、`not`；优先级与括号；短路时右侧表达式不求值。先让逻辑两边都是布尔值或比较结果，后课再讨论一般对象的真值。打印布尔结果不等于按不同情况执行不同业务步骤。

**理论总结：** 比较产生判断结果；逻辑运算组合判断，而且可能跳过不需要的右侧求值。

| 步骤 | 要抄写的内容 | 要观察与解释的结果 |
| --- | --- | --- |
| step01-comparisons | 保存启用标记和额度数据，打印等于、大于等比较结果 | True 与字符串 "True" 的角色不同；== 不做赋值 |
| step02-combined-rules | 组合启用与额度条件，比较 and/or/not 与括号 | 同一组事实在不同组合规则下可能有不同结果 |
| step03-short-circuit | 先单独观察零除失败，再用固定真假左操作数对照是否求值右侧 | 解释跳过表达式的原因；不为此定义辅助函数 |

**错误与练习：** 小写 true 作为名称会失败；将 and 理解成“无论如何两边都执行”会预测错误。练习分别替换固定启用标记和额度，列出几组输入与预期布尔值，不写循环枚举。

**验收与边界：** 能解释逻辑结果及被跳过的表达式。实际“启用时输出 A、否则输出 B”留到阶段 03；不能教 `and/or` 是永远返回 bool 的运算，004 用简单字符串进一步澄清它们返回操作数的行为。

### 02-004：表示缺失的订单备注

**前置与问题：** 已学 003。备注没提供、提供了空文本、曝光为零和启用为假，是不是同一件事？

**核心理论：** None 表示没有提供一个有意义的值；名称绑定到 None 与名称尚未定义不同；None、空字符串、0、False 的类型及业务语义不同。引入 bool 观察真值，它们都可能为假，但不因此成为同一个对象或同一种数据。教会 `is None`、`is not None` 的使用，身份机制在 006 展开。

补充逻辑返回值：用已学简单值对照 `"备注" or "默认文字"` 与 `"" or "默认文字"`，观察结果及类型，明确 and/or 返回操作数而非强制布尔值。把空字符串当成缺失是否合理，取决于业务约定，不能用这个写法替代显式缺失判断。

**理论总结：** 真值相同不等于业务含义相同。判断“是否缺失”要表达缺失条件，不随意把所有假值合并。

| 步骤 | 要抄写的内容 | 要观察与解释的结果 |
| --- | --- | --- |
| step01-missing-versus-empty | 分别保存 None、空文本、零与 False，打印值和 type | 空文本看似没显示，None 有可见表示；类型和语义分开 |
| step02-truth-values | 对每个值调用 bool，再观察非空字符串 "False" 的真值 | 真值转换不解析单词代表的业务布尔含义 |
| step03-missing-check | 打印 is None/is not None 的结果，再观察简单 or 表达式的返回值 | 精确缺失判断与通用真值选择不同 |

**错误与练习：** 对比读取未定义名称的 NameError 与读取已绑定 None 的正常行为；练习为缺失备注、空备注、零曝光分别说明应保留的信息。

**验收与边界：** 能选择缺失表示并解释真值，避免断言“None 等于任何空值”。不使用列表/字典、if、Optional 或校验框架。

### 02-005：转换模拟输入的数据

**前置与问题：** 已学 004。模拟外部输入 "1200" 看起来是曝光数，为什么不能直接当整数参与所有计算？

**核心理论：** 字符串内容与数值对象的区别；int、float、str 的调用、输入与返回；转换得到另一个值并可重新绑定名称，不是把已有字符串原地改造成整数；合法字符内容与转换要求；转换失败的 ValueError/TypeError；int 对有限浮点数向零截断，区别于 002 的向下整除。

**理论总结：** 转换遵守函数规则，不替你判断业务是否合理。先知道原始类型和格式，再选转换方法。

| 步骤 | 要抄写的内容 | 要观察与解释的结果 |
| --- | --- | --- |
| step01-raw-text | 以固定字符串模拟曝光输入，打印原始类型并单独复现字符串加数字错误 | 格式看起来像数字不代表已经是数值对象 |
| step02-explicit-conversion | 把整数文本转成 int、小数文本转成 float，数值用 str 展示 | 转换前后类型不同；原始名称仍可保留用于对照 |
| step03-conversion-boundaries | 分文件比较 "12.5"、空字符串、None 与有限浮点数到 int | 非法转换失败；浮点转 int 可能成功但丢失小数 |

**错误与练习：** 独立失败文件复现 int("12.5")、int("")、int(None)；复述 bool("False") 为真不等于业务标记为真。练习转换合法的模拟曝光与天数并计算日均；为不合法输入说明失败原因。

**验收与边界：** 不用 int(float(...)) 作为“万能修复”，避免悄悄改变数据含义。无真实接口、input()、JSON、正则、字符串清洗方法或 try/except；这些分别在后续课程引入。

### 02-006：比较两个订单编号

**前置与问题：** 已学 005。两份数据内容相同，是否意味着它们就是同一个对象？

**核心理论：** `==` 比较值的相等关系，`is` 判断对象身份；再次绑定与原对象、别名的关系；None 检查为什么习惯用 is。只讨论本阶段内置简单类型的行为，比较协议和自定义对象的相等规则留到阶段 08。

避免用两个相同整数字面量的 is 结果作跨版本固定答案。语言实现可能复用不可变对象；即使某次结果为真，也不能推出 is 适合比较数值或字符串内容。官方 [身份与字面量说明](https://docs.python.org/3/reference/expressions.html#literals) 可辅助核对这些边界。

**理论总结：** “值相等”和“同一个对象”回答不同问题，业务编号内容比较使用 ==。

| 步骤 | 要抄写的内容 | 要观察与解释的结果 |
| --- | --- | --- |
| step01-value-comparison | 用两份模拟编号文本比较内容，再改变其中一份 | 内容相等与不等都通过 ==/!= 观察，不依赖字符串驻留 |
| step02-alias-and-rebind | 一个名称赋给另一个名称，再把前者绑定到不同值 | 别名最初指向同一对象；重新绑定前者不改变后者 |
| step03-equal-not-identical | 对照数值相等的 int 与 float，例如 1000 和 1000.0 | 内置数值的 == 为真；类型不同，不可能是同一个对象；这不是整数缓存实验 |

**错误与练习：** 展示“用 is 比较订单编号”的概念错误，不要求它必然报异常；纠正为内容比较。练习解释同值不同类型、别名和 None 三种情形该选什么比较。

**验收与边界：** 能解释稳定案例，不拿具体 id 数字当内存地址知识，也不引入 object()、列表、类定义来凑例子；可变对象和拷贝留到阶段 04。

### 02-007：计算小数与预算

**前置与问题：** 已学 006。为什么 0.1 加 0.2 的浮点结果与想象中的十进制表示不同？预算保留两位小数究竟是在改变数值还是只改变显示？

**核心理论：** 常见 float 使用二进制近似表示，有限二进制位不能精确表达所有十进制小数；输入、运算和显示要区分。引入 decimal 标准库，用 `import decimal` 延续第一阶段模块访问形式；解释 Decimal 从字符串构造、对象方法调用和显式舍入参数。

Decimal 并非无限精度：某些有限十进制输入可以精确表示，但算术受上下文精度与舍入影响；循环小数也不能因此变成无限精确结果。当前用简单金额与数量演示，不把 Decimal 描述成任何数值问题的万能解决方案。

**理论总结：** 先选适合数据含义的表示，再明确计算和舍入规则；从已有浮点数构造 Decimal 不会自动恢复原始十进制输入。

| 步骤 | 要抄写的内容 | 要观察与解释的结果 |
| --- | --- | --- |
| step01-float-observation | 对照 0.1 + 0.2 与 0.3，观察显示和值比较 | 解释近似来源，不把偶然显示简短误判为内部精确 |
| step02-decimal-input | 从 "0.1"、"0.2"、"19.90" 等文本构造 Decimal 并计算 | 对比从 float 构造的结果，说明误差不能在转换时凭空消失 |
| step03-rounding-policy | 用 quantize 明确两位小数与 ROUND_HALF_UP，对照预算结果 | 首次详细拆解方法名、位置参数、rounding 关键字参数和常量来源 |

**错误与练习：** 独立复现 Decimal 与 float 混合算术的类型错误；解释内置 round 不能概括成任何情形都“逢五进一”。练习从价格文本与整数数量计算总价，并按题目指定舍入规则给出结果。

**验收与边界：** Decimal 构造与方法调用作为本课工具知识详细解释，不先要求掌握类定义或函数参数完整体系；不使用 with/localcontext、异常捕获、金融业务法规或复杂精度配置。更深入数值专题再处理上下文、信号和特殊值。

### 02-008：生成指标说明

**前置与问题：** 已学 007。怎样把散落的变量和值计算成一份清楚的指标说明，同时保留原始数值便于继续计算？

**核心理论：** f-string 的 f 前缀、花括号内求值、标签与表达式的区别；格式说明 `.2f` 与 `.2%`；百分数显示会按比例格式化，避免先乘 100 再用百分数格式造成重复放大；格式化结果是字符串，不等于原始对象被改成所显示的小数位。首次详解花括号和冒号，不靠直接复制最终长字符串。

**理论总结：** 数据、计算结果和展示字符串分开。先算，再显示；显示精度不能替代计算精度或业务舍入规则。

| 步骤 | 要抄写的内容 | 要观察与解释的结果 |
| --- | --- | --- |
| step01-calculated-values | 用变量保存名称、实际曝光、目标、天数与价格，先分行打印计算值 | 所有正常样例分母明确为正；保留原始值便于核对 |
| step02-formatted-report | 用 f-string 输出名称、曝光量、日均、完成率与预算 | 逐个加入插值、两位小数、百分数和已学 Decimal 结果，不一次塞满格式选项 |
| step03-revised-input | 保留前版，在完整新版本修改输入、重新计算并生成说明 | 结果随输入改变，类型与显示职责保持清楚 |

**正常样例验收数据：** 实际曝光 1250，目标曝光 5000，天数 2；日均显示 625.00，完成率显示 25.00%。价格文本 "19.90"、数量 3 的预算按两位小数显示 59.70。变式把实际曝光改为 2200，日均显示 1100.00，完成率显示 44.00%；在题目中明确没有另改预算输入。

**错误与练习：** 故意忘记 f 前缀可观察花括号原样显示；重复乘 100 可观察百分比放大。目标为零、天数为零分别放独立失败文件，观察 ZeroDivisionError；正常版本不能因把分母换成 1 或返回 0 而掩盖无效数据。练习独立修改输入、预测结果并说明格式化前后类型。

**验收与边界：** 无 if、条件表达式、try/except、循环或函数定义。无效分母在本阶段只识别失败并人工修正；阶段 03 的 03-001 再实现“先判断数据有效，再计算与分类”的运行流程。
